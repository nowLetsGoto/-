
## 审计日志下放公司管理员 + 补齐审计覆盖（§24，已完成）

### 实现
仓储早就支持 tenant 过滤，缺的只是入口。三处改动：
1. 后端：审计从 admin 组（RequireSuperAdmin）移到独立组 RequireMinLevel(platform_admin) + InjectScope + RequireTeamMode
2. 前端菜单：审计从「平台管理」移到「公司设置」（platform_admin 组）
3. 前端守卫：AdminGate → LevelGate(platform_admin)

### ⚠️ 必须同时加 RequireTeamMode（关键安全点）
solo.audit_logs 分区**不做 tenant 过滤**（个人工作台无租户概念）。
若允许 solo 模式查询，平台管理员 solo 登录就能读到全平台单人用户审计 = 跨公司泄漏。
代价：超管 solo 也看不到审计（刻意取舍），Sidebar soloAllowed 同步移除。

### 顺带补的缺口：审计只覆盖少数动作
实测平台管理员拿到 0 条 —— 不是过滤错，是人员/团队/项目**从不写审计**（handler 无 audit 依赖）。
补齐 9 个动作：person/team/project × created/updated/deleted。
- person.updated / project.updated 带 roleKey（改角色是影响权限最大的动作）
- team.updated 带成员数与项目数（关联变化直接改变可视范围）

## 团队负责人横向越权修复（§25，已完成）

### 问题本质
团队隔离只做在「读」（人员/团队/项目的仓储查询），「写」完全没用到 TeamScoped。
同一模式三处实现不一致：people.Delete/teams.Delete 靠前置 Get 挡住；
people.Update 靠 handler 的 Get 挡住；teams.Update 和 user.* 什么都没挡。

### 修复（方案 C）
**守卫层** service/user：
- ensureInScope 三层：超管 → 公司 → 团队，越界一律 404
- ensureTeamScope：只管自己团队的 member + 自己；team_admin 及以上一律不可（防平级互停）
- ensurePersonAssignable：除超管外必须绑定人员；team_admin 还要求本团队

**仓储兜底**：
- user.applyTeamBoundary：自己 OR (member AND 人员在我团队)
- people.save/Delete、teams.save/Delete 补 ApplyTeam

**Scope.SelfUserID 新增字段**：team_admin 的团队关联在 team_admins 不在 team_members，
不加这项它在账号列表看不到自己。

### 顺带修的两个真 bug（验证时发现的）
1. teams.save / people.save 的 UPDATE **参数漏传** → 500。原因：加了 ApplyTeam 后条件多一个数组参数，
   但调用点仍手写 `scope.TenantID, id` 列表。修法：`append([]any{SET部分}, filter.Args()...)`。
   **教训：加动态条件必须用 filter.Args()，手写参数列表迟早错位。**
2. 团队负责人建团队 → 404 但已入库，留下 0 管理员 0 成员的孤儿团队（末尾 FindByID 看不到刚建的行）。
   修法：TeamScoped 禁止新建团队 + 前端入口按 platform_admin 隐藏。

### 前后端对齐
前端原本就强制非超管绑定人员，后端只要求 team_admin → 统一为「除超管外都必须绑定」。

### 验证 17 项
账号读/改/删/重置密码/停用全 404、列表只剩自己、改别团队 404 且数据未变、用别团队人员建账号 400、
管另一负责人 404、建团队 403 无新增、必须绑定人员 400、正常功能未破（能改自己团队、能管本团队账号）。

### 遗留
translate 把 NotFound 统一映射成「包不存在或已被移除」，用于团队/人员措辞不准（既有问题）。

## 全局错误文案重构（§26，已完成）

### 问题
contract.ErrNotFound 文案写死「包不存在或已被移除」，被 20+ 处返回，
覆盖团队/人员/角色/公司/账号，全部串场。另有 3 个同名 translate 函数做三件不同的事。

### 设计（一处定义，两处生效）
1. 资源名集中成 contract 常量：ResourceBuild/Project/Person/Team/User/Role/Tenant/File
2. NotFoundError 统一生成句式 "{资源}不存在或已被移除"；**不提供自带整句文案的构造函数**（那是漂移根源）
3. **关键：NotFoundError.Is(target) 让它与 ErrNotFound sentinel 等价**
   → 仓储返回资源化错误，10+ 处 errors.Is(err, ErrNotFound) 判断无需改
   → 「改文案」与「改判定」解耦
4. 兜底 sentinel 改中性文案「该资源不存在或已被移除」
5. EnsureDeleted 第二参数从表名改为上屏资源名
6. 三处 translate 按真实职责重命名：noRowsToInvalidProject / constraintConflictToMessage

### 验证 8 类资源
团队/人员/角色/账号/应用包/公司各自准确 404，项目是 400（按设计：key 属于参数错误），零串场。
errors_test.go 钉文案 + errors.Is 穿透；response_test.go 钉 404 映射。

### 教训
**资源名是唯一变量，句式必须一处生成。** 允许各处传整句文案 = 必然漂移。
**sentinel 与结构化错误要兼容**：实现 Is() 方法即可平滑迁移，不必一次性改所有判断点。

## 新建角色 500 修复（§27，已完成）

### 根因 1（主 bug）：findByID 漏配 fromClause
§23 给 role 仓储的 columns 加了 r. 别名 + coalesce(t.name,'')，要求所有查询拼 fromClause。
但 save() 末尾回读用的 findByID 仍是裸 `FROM roles` → SQL 报错 → 500。
**单测不连库所以没发现**：所有角色测试都是纯函数断言，新建/编辑/回读链只有真跑才走到那条 SQL。
修法：findByID 改用 columns+fromClause+' WHERE r.id=$1'；
新增 columns_test.go 用源码静态检查钉死「columns 与 fromClause 必须配套」。

### 根因 2（连带发现）：schema.sql 迁移把空串 API Key 哈希成同一个值
`WHERE length(api_key) <> 64` 把空串也算进去 → 哈希成 e3b0c442...（空串固定摘要），
每家未配置 Key 的公司得到同一个值 → 撞 idx_settings_api_key 唯一索引 → 启动失败。
修法：条件加 `AND api_key <> ''`（空串是「未配置」标记，不是待哈希明文）。
**没有改任何真实 Key 数据**。

### 验证
平台管理员建角色 201、编辑 200、回读正确；12 包全绿。
超管直接建角色得 400 是既有设计（超管无公司归属），非 bug。

### 教训
**共享 SQL 片段（columns/fromClause 这类）必须有配套约束测试**，否则改了片段，
漏改的调用点在单测里完全静默，只在真实执行时 500。
