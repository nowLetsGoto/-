# 2026-11-17（下午）前端：单人模式「零项目」引导修复

## 用户问题
截图现场：单人模式普通用户（zouliang）访问 `/p/web/packages`，页面显示红色 `488 项目不存在，请刷新项目列表后重试`，而不是像 admin 那样给「去创建项目」的引导。

## 根因
不是「空包状态」问题，是**项目守卫漏判**。`web/src/hooks/useProjects.ts` 里：
```ts
const notFound = !loading && projects.length > 0 && project === null;  // 旧
```
`projects.length > 0` 这个前置条件让「一个项目都没有」时 `notFound=false`，守卫放行，
页面带着地址栏里的废 key 去请求 `/builds`，后端只能回 488。

## 改动（3 个文件）
1. `web/src/hooks/useProjects.ts`
   - `CurrentProject` 新增 `empty: boolean`
   - `notFound` 去掉 `projects.length > 0`：`const notFound = !loading && project === null;`
   - `const empty = notFound && projects.length === 0;`
   - 关键：`empty` 把「零项目」与「key 失效」两种成因分开，因为二者该给的引导不同
2. `web/src/components/ProjectGate.tsx` 按单一职责拆分
   - `ProjectScopedGate`：只做事实判定 + 分流（`empty ? <NoProjectYet/> : <ProjectMissing/>`）
   - 新增并导出 `NoProjectYet`：零项目 → 唯一动作「新建项目」，链接 `/directory/projects/new`
   - `ProjectMissing`：key 失效 → 「回到最近项目」+「去项目管理」；内部加 `if (!fallback) return <NoProjectYet/>` 兜底（同时满足 TS 收窄）
3. `web/src/App.tsx`
   - `ProjectHome` 的零项目分支改复用 `<NoProjectYet/>`，删掉各写一套的 `<Empty>`，文案不再两处不一致

## 权限前提（已验证，不是猜测）
- `server/internal/service/authz/service.go` 的 `soloPermissions()` 含 `project.write` → 单人普通用户可自建项目
- `web/src/components/navigation.ts` + `Sidebar.tsx` 的 `soloAllowed` 含 `/directory/projects` → 菜单可达
- `ProjectFormPage` 的 `solo` 分支不请求角色列表 → 单人建项目不会因 `role.read` 缺权而崩

# 2026-11-17（晚）四项需求：模式列 / tab 换库 / 删除账号 / 侧栏账号卡 + 改密

## 需求与落点

| 需求 | 落点 |
|---|---|
| 审计日志加「模式」列 | 后端 `contract.AuditLog.Mode` + `Partition.Mode()` + 仓储回填；前端表格插列与抽屉补行 |
| tab 换组件库并修垂直居中 | 五处手写 tab 全换 `Controls.Segmented`；删掉 `.segment*` / `.env-*` 两组死样式 |
| 账号管理删除账号 | `DELETE /admin/users/{id}` + 行内按钮 + 二次确认弹窗 + 成功提示 |
| 侧栏头像弹层（模式 / 改密 / 退出） | 新组件 `AccountMenu`（Popover 向上弹）+ `ChangePasswordDialog` + `PUT /me/password` |

## 关键技术判断（都是验证过的，不是推测）

- **「模式」列零迁移**：`solo.audit_logs` / `team.audit_logs` 是按模式物理分区的，分区身份本身就是模式。加 `Partition.Mode()` 逆映射后由仓储在循环外算一次 `mode` 再回填，不用加列、不用改 DDL、不用回填历史。
- **垂直居中根因**：`styles.scss` 里 `.segment { display: inline-flex; align-items: baseline; }` —— `baseline` 就是「字体没有垂直居中」的直接原因。换库时把这一整组死样式删掉，问题随根因一起消失，不需要再叠 `line-height` 补丁。
- **删除账号无级联障碍**：`projects` / `builds.owner_user_id` 都是 `TEXT` 非 FK，`users` 表唯一外键是 `person_id → people(id) ON DELETE SET NULL`，所以 `DELETE FROM users` 不会被挡，历史构建与审计日志也不丢（`actorName` 是冗余存储）。
- **改密必然踢下线**：`SetPassword` 一定自增 `token_version`，旧令牌当场失效。产品决策定为「改密成功即清会话回登录页」，而不是换发新令牌把用户留在原地——后者要在失效瞬间做令牌轮换，复杂且收益为零。
- **antd 会在两个中文字之间插空格**：`okText="删除"` 渲染出的 DOM 文本是「删 除」，Playwright `has-text("删除")` 匹配不到。自动化里确认按钮一律按 `.ant-modal .ant-btn-primary` 定位。
- **`Popover` 的 `overlayStyle` 不生效**（类型可疑且实测无效），宽度改由 `.account-card { width: 240px }` 决定。
