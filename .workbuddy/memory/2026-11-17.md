# 2026-11-17（下午）前端：单人模式「零项目」引导修复

## 用户问题
截图现场：单人模式普通用户（zouliang）访问 `/p/web/packages`，页面显示红色 `488 项目不存在，请刷新项目列表后重试`，而不是像 admin 那样给「去创建项目」的引导。

## 根因
不是「空包状态」问题，是**项目守卫漏判**。`web/src/hooks/useProjects.ts` 里：
```ts
const notFound = !loading && projects.length > 0 && project === null;  // 旧
```
`projects.length > 0` 这个前置条件让「一个项目都没有」时 `notFound=false`，守卫放行，
页面带着地址栏里的废 key 去请求 `/builds`，后端只能回 488。

## 改动（3 个文件）
1. `web/src/hooks/useProjects.ts`
   - `CurrentProject` 新增 `empty: boolean`
   - `notFound` 去掉 `projects.length > 0`：`const notFound = !loading && project === null;`
   - `const empty = notFound && projects.length === 0;`
   - 关键：`empty` 把「零项目」与「key 失效」两种成因分开，因为二者该给的引导不同
2. `web/src/components/ProjectGate.tsx` 按单一职责拆分
   - `ProjectScopedGate`：只做事实判定 + 分流（`empty ? <NoProjectYet/> : <ProjectMissing/>`）
   - 新增并导出 `NoProjectYet`：零项目 → 唯一动作「新建项目」，链接 `/directory/projects/new`
   - `ProjectMissing`：key 失效 → 「回到最近项目」+「去项目管理」；内部加 `if (!fallback) return <NoProjectYet/>` 兜底（同时满足 TS 收窄）
3. `web/src/App.tsx`
   - `ProjectHome` 的零项目分支改复用 `<NoProjectYet/>`，删掉各写一套的 `<Empty>`，文案不再两处不一致

## 权限前提（已验证，不是猜测）
- `server/internal/service/authz/service.go` 的 `soloPermissions()` 含 `project.write` → 单人普通用户可自建项目
- `web/src/components/navigation.ts` + `Sidebar.tsx` 的 `soloAllowed` 含 `/directory/projects` → 菜单可达
- `ProjectFormPage` 的 `solo` 分支不请求角色列表 → 单人建项目不会因 `role.read` 缺权而崩

## 验证方式（不依赖真实后端数据）

用 `page.route('**/api/v1/**')` 拦截 mock 四种场景，断言页面文案与**是否真的发出了 `/builds` 请求**：

| 零项目 + 失效 key `/p/web/packages` | 「还没有项目」+「新建项目」，无 488 | ✅ 无 `/builds` 请求 |

| 有项目 + key 失效 `/p/gone/packages` | 「项目「gone」不存在」+ 回到最近项目 | ✅ 未误判成零项目 |
