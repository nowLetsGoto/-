# 2026-11-16 · Dandelion 登录功能（前后端打通）

## 目标
给 Dandelion 增加管理员登录，未登录不能上传/发布/看列表，登录后进入包列表页；登录页主题为浅色 + 浅蓝青。

## 后端（Go）
- 契约 `api/openapi.yaml`：新增 `POST /auth/login`、`LoginRequest/LoginResult/LoginResponse`、`401 Unauthorized`、`securitySchemes.bearerAuth`、`x-constants.authTokenTTLSeconds=43200`，以及 `limits.username/password`。
- 新增 `service/auth_service.go`：单管理员账号 + 无状态 HMAC 令牌（载荷只有到期时间戳，`crypto/subtle` + `hmac.Equal` 定长比较），token 形如 `exp.signature`。
- 新增 `handler/auth_handler.go`、`middleware/auth.go`（Bearer 解析 + 401）。
- 路由分组：`POST /builds/stage`、`POST /builds`、`GET /builds` 需登录；`GET /builds/{id}`、`GET /builds/{id}/file`、`/healthz`、静态资源保持公开（扫码下载链路不能挡）。
- 配置新增 `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `AUTH_SECRET`：生产沿用默认密钥 fail-fast。
- `handler.DecodeJSON` 增加 `allowed` 参数（原实现把 commit 的 8 个字段写死在错误文案里）。
- 错误码扩展为 400/401/404/405/413/500：**凭据错误走 400，令牌失效走 401**，前端只需对 401 做统一跳转，不必特判登录接口。

## 前端（React）
- `web/src/pages/login/LoginPage.tsx` + `login.css`：左品牌场（渐变 + 同心圆 + 种子浮动）+ 右极简表单，局部 `--login-*` 变量，移动端单栏。
- `api/session.ts`：localStorage 唯一读写处；`api/auth.ts`：登录调用；`client.ts`：注入 Bearer，401 时清会话并整页跳 `/login`。
- `App.tsx`：`RequireAuth` + layout route（`<Layout><Outlet/></Layout>`）；`/d/:id` 公开；`Layout` 增加账号区与退出（无会话时不渲染）。

## 2026-11-16 · 更正：登录代码改为「按层的功能子目录」

**我理解错了**：用户要的不是垂直切片 `internal/auth/`，而是**在每个层目录下建同名功能子目录**：

```
internal/handler/login/handler.go        HTTP 语义
internal/service/login/service.go        凭据 + 令牌（含 service_test.go）
internal/middleware/login/middleware.go  鉴权中间件
```

- 三层包名都叫 `login`，import 时起别名：`loginhandler` / `loginsvc` / `loginmw`。
- 依赖方向：`handler/login → handler（父包，复用 OK/WriteError/DecodeJSON）+ service/login`；
  **父包不得 import 子目录**（`go list -deps ./internal/handler | grep login` 应为空）。
- 登录不落库 ⇒ **没有** `repository/login`，不建空壳目录。
- 规范已写进 `docs/06-FOLDER-LAYOUT.md`：§3 包表、§4 禁止项、§5 决策行 13、§6 新增「功能子目录」约束。

**教训**：用户说「统一管理」时，先确认是「一个功能一个包（垂直切片）」还是「一层一个目录、里面再按功能分（水平+功能子目录）」。这个仓已有的 `parser`/`storage` 是领域包，但 `handler/service/repository` 是层，用户要的是后者的细分。

## 2026-11-16 · 修「一个页面拉一堆接口」

**现象**：人员管理页同时请求 `/people`、`/teams`、`/projects`（还有 `/me`）。

**三个根因，逐个修掉**：
1. `useDirectory` 把人员+团队合成一次加载 → 拆成 `usePeople` / `useTeams` 两份独立缓存（同一个文件，共用 `useCachedList` 泛型）。
2. 列表要显示关联名字，只能再拉对方列表 → **后端列表接口直接返回 `RelationRef{id,name}`**（`Person.teams/projects`、`Team.persons/projects`、`ProjectDetail.persons/teams`）；写接口仍收 ID 数组，保存后按 id 重查一次拿名字。
3. 布局层顺带取数：`Sidebar` 用 `useCurrentProject`（内含项目列表请求）、`Topbar` 的 `ProjectCrumb`、`ProjectGate` 无条件挂 hook → `useProjectKey` 改成只读 URL/localStorage 不取数（无 key 时 `navHref` 退回 `/`）；`ProjectCrumb` 与 `ProjectScopedGate` 只在项目内路径挂载。

**结果**（Playwright 实测请求数）：
```
/directory/people   → 1 个：GET /api/v1/people
/directory/teams    → 1 个：GET /api/v1/teams
/directory/projects → 1 个：GET /api/v1/projects
```

**规则**：列表页只允许挂自己的那个列表 hook；关联展示一律靠接口带回的名字，不允许前端二次拉取。

## 2026-11-16 · 服务端分页 + 项目详情抽屉

### 后端分页（人员 / 团队 / 项目）
- `contract.PageQuery{Page,PageSize}` + `Page{page,pageSize,total}`；`Limit()` 在 PageSize<=0 时返回 1<<30（不分页取全量），`Offset()` 同理归零。
- 三个 List 改为 `(ctx, page) (items, total, error)`：先 `count(*)` 再 `LIMIT $1 OFFSET $2`。
- 关联查询用 `WHERE xxx_id = ANY($1::uuid[])` 只捞本页的关联，不再全表扫关系行。
- `handler.ReadPage` 统一归一化：page 非法→1；pageSize 缺省→10、显式 0→全量、上限 200。
- 契约加 `PageParam`/`PageSizeParam` 两个公共参数（放 `components.parameters`），三个列表响应 `data` 平铺 total/page/pageSize。
- **踩坑**：批量替换 `  parameters:` 时误命中操作内的 parameters 键，把 components 段写进了 operation，导致 YAML 缩进错误 + 重复键。教训：改 YAML 用锚点定位，不要用会被多次匹配的短串。

- `usePageState`：分页参数放 URL（`?page=&pageSize=`），刷新后停原页；`replace: true` 避免后退键在页码间跳。
- `DataTable` 加 `serverPagination`：传了走受控分页，不传退回前端分页（应用包列表仍是前端分页，它还要被概览聚合）。
