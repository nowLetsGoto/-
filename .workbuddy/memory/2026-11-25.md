## 四服务后台常驻方案（文件已备好，待用户终端执行安装）

### 设计决策
用户想"自动执行 make dev + cloudflared tunnel + 不受熄屏影响"。
判断 make dev 不适合直接交给 launchd：它用 & 起两个子进程再 wait，
launchd 只能监控 make 父进程——后端崩了但 Vite 活着时 make 不退出，不会重启，公网已断。
故拆成四个独立 LaunchAgent，各自 KeepAlive：
1. com.dandelion.server   生产版后端 10088（serve-production.sh 加载 .env）
2. com.dandelion.vite     本地开发 5173（npm run dev），仅供开发，公网不指向它
3. com.dandelion.tunnel   cloudflared → 10088
4. com.dandelion.keepawake caffeinate -i -s 阻止空闲休眠（不加 -d，允许熄屏）
用户确认公网走生产版 10088（非 Vite 5173）。

## 后台服务安装失败诊断（13:56，重要）

### 现象
用户执行 install-autostart.sh 后：server 与 tunnel 服务 last exit code = 78 (EX_CONFIG)，
vite 与 keepawake 正常运行。公网 530。

### 诊断过程
- 脚本本身在最小 PATH 环境（env -i PATH=/usr/bin:/bin:...）下能正常启动 ✅
- shebang 正常（#!/bin/bash + LF）✅
- 日志目录可写 ✅
- server.err.log 未创建 → launchd 在执行程序前就失败

### 根因判断
EX_CONFIG + 不写日志 = launchd 拒绝执行 program 文件本身。
对比成功的 vite plist：它用 /bin/bash -lc 包裹命令；失败的两个直接把脚本/二进制当 program。
推测 launchd 对直接执行用户目录脚本或 homebrew symlink 有 TCC/spawn 限制。

### 修复
把 server / tunnel 两个 plist 改成与 vite 相同的包裹模式：
  ProgramArguments: ["/bin/bash", "-lc", "exec <绝对路径> <args>"]
已重写并 plutil 校验通过。

### 当前状态
本会话仍无法 bootstrap（I/O error 权限限制），已从 launchd bootout，
临时用手动进程恢复公网 200。
需用户重新执行 install-autostart.sh 加载新 plist 验证。

## 后台服务 78 的真正根因（14:04 日志确认，已修复）

### 决定性日志
用户在终端 log show 抓到：
  Service could not initialize: posix_spawn(/bin/bash), error 0x1 - Operation not permitted
  xpcproxy exited due to exit(78)

### 根因
这台 Mac 的安全策略禁止 launchd spawn /bin/bash（即使 vite 的 bash 版本之前"看起来"成功，
server/tunnel 经 bash 启动必被拒）。不是 plist 语法、不是冷却期、不是命令本身——
验证：同样的命令在 env -i 最小环境下手动执行完全正常。

### 修复（关键教训）
plist 里**绝不要用 /bin/bash -lc 包裹**。改为：
- server: ProgramArguments 直接指向 bin/dandelion 绝对路径；
  环境变量通过 plist 的 EnvironmentVariables 字典内联（从 .env 生成，HTML 转义）。
- tunnel: ProgramArguments 直接指向 cloudflared 真实路径
  /opt/homebrew/Cellar/cloudflared/2026.11.2/bin/cloudflared（绕开 symlink）。
- 两个 plist 已确认 grep bash = 0 处，plutil 校验 OK。
- 内联环境变量直接执行二进制已验证能正常启动。

### 通用原则（写进长期记忆候选）
macOS launchd LaunchAgent 若报 EX_CONFIG(78) 且日志有 posix_spawn(...): Operation not permitted，
说明该可执行文件被系统策略禁止 spawn。解决：plist 直接列可执行文件路径 + EnvironmentVariables，
不要用 shell 包裹，不要用 symlink。

### 🔑 核心根因（反复踩了 6 次才找到）
launchd 报 EX_CONFIG(78) + 日志 `posix_spawn(/bin/bash): Operation not permitted`
**不是** bash 被拦、**不是** plist 语法、**不是** 冷却期。
真正原因：**macOS TCC 保护 Desktop/Documents/Downloads** ——
launchd 启动的程序不能执行这些目录下的二进制，也不能把工作目录设在那里。
vite 能成功是因为它实际执行 ~/.workbuddy 下的 npm（Desktop 只是 cd 路径）。

解决：二进制搬到 ~/dandelion-runtime/dandelion，STORAGE_DIR 用绝对路径指回原 storage。

### 其他教训
1. **助手会话里启动的后台进程会被回收**（& / nohup 都一样），
   表现为"启动30秒后200变000"。只有 launchd 能真正常驻，
   不要用手动进程验证长期可用性。
2. launchd 的 PATH 只有 /usr/bin:/bin:/usr/sbin:/sbin，
   环境变量必须用 plist 的 EnvironmentVariables 内联，不能靠 .env。
3. 项目内端口已统一 10088（.env/vite代理/config.go默认值/README/隧道/安装脚本）。
