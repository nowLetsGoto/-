### 踩坑（重要）
1. `INSERT ... SELECT $1, id` 里纯常量投影参数 PG 无法推断类型 → 必须写 `$1::uuid`。

## 修复：换账号后报「项目不存在」（§20，已完成）

### 现象
登录平台管理员账号首屏报错。接口复现：GET /builds?project=default → 400 项目不存在。

### 三个成因（都在前端本地状态，不在服务端）
1. **useProjects 的模块级 cache 不随身份失效**（主因）。只靠 invalidateProjects() 在新建/编辑后清，登出/换账号不清 → 乙账号读到甲账号的项目列表。同仓 useMe 早就按 token 绑缓存（cacheToken===token），useProjects 漏了同样处理。
   修法：cache 改成 {owner, items}，owner = `username|mode`，读取时比对；invalidateProjects 同时清 inflight。
2. **localStorage 的 dandelion.project 按浏览器存不按账号存** → 换账号后用别人的项目 key 请求。
   修法：session.ts 里集中 IDENTITY_SCOPED_KEYS，clearSession() 与 saveSession() 检测身份变化时统一清；同身份重登不清（避免无谓重置）。
3. **ProjectGate 加载期间放行** → notFound=!loading && project===null，loading 时 notFound=false → children 渲染 → 概览页拿未验证 key 请求 → 先闪一条错误。修法：loading 期间不渲染 children，给 Loading。

### 验证
Node 模拟缓存逻辑 7/7：乙不拿到甲的项目、直接换账号缓存失效、同用户换模式清理、同账号重登保留。
四道门禁全绿，数据已清理（保留用户手动建的「世界第一家公司」）。

### 经验（重要）
**模块级缓存必须与登录身份绑定**。这是第二次遇到同类问题（useMe 做对了、useProjects 漏了）。
以后新增任何 module-level cache，一律存 owner 并比对。
localStorage 里凡是"上次看过什么"这类状态，都要列进 IDENTITY_SCOPED_KEYS。

## 「设为超级管理员」对平台管理员可见（§22，已修）

### 结论：不是越权漏洞，是前端体验缺陷
后端守得很严（实测 9 项全过）：
- 平台管理员 POST 带 isSuperAdmin:true → 403
- 平台管理员 PUT 他人带 isSuperAdmin:true → 403，库中未变
- 平台管理员账号列表**不含超管账号**；按 id 读/改/删超管全 404（不透露存在）

### 真正的问题
AccountFormPage 的「设为超级管理员」复选框**无条件渲染** → 平台管理员看到注定 403 的开关。
比看不到更糟：误以为自己有权力，点完被拒不知是 bug 还是权限不足。

### 设计原则（重要）
**「界面上不提供无法成功的操作」比「依赖后端兜底」更好。**
后端负责安全边界，前端负责不误导。两者职责不同，不能互相替代。
前端条件渲染判据必须与服务端守卫一致（这次都是 me.isSuperAdmin）。

### 修法

避免后人误以为前端这层是安全边界。

## 排查记录：「正在读取项目…」卡死 = dev server 被挂起（2026-11-18）

现象：页面一直转圈，控制台无报错，只有 vite 连接日志。
判据：`curl` 能 connect 但 4 秒收不到任何字节（`healthz:000` / exit 28），
而 `lsof` 显示端口在 LISTEN、数据库只有 4 条 idle 连接（不是连接池/锁问题）→
进程被 SIGTSTP（终端 Ctrl+Z）挂起。`kill -CONT <pid>` 后 healthz 立刻 200。
注意：本次只恢复了后端（60214），vite（60235）SIGCONT 无效，仍在卡死，
需在跑 `make dev` 的终端 `fg` 或 Ctrl+C 后重跑。
结论：以后遇到"能连上但零响应"，先怀疑进程被挂起，而不是代码死循环。

## 角色与身份彻底分离 + 内置角色每公司独立副本（§23，已完成）

- 超级管理员 = 账号身份，全平台固定，permissionsOf 第一步短路，从不查角色
- 平台管理员 = 账号身份（account_level），超管建公司时连带创建
