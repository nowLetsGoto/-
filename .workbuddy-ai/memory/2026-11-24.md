### 本轮 2 个真实 bug（均由 QA 探针触发、lead 复现定位）
**Bug 1｜三协议在上游「200 但无 usage」时 `TokensReported` 错报 true，token 写 0**
- 根因：三解析器把 `usageFrom(..., reported=true)` 硬编码 true，注释理由「json 零值无法分辨」**是错的**——`*int` 指针可区分 nil（字段没出现）与非 nil 的 0（真实上报）
- 修复：`inputOutputUsage` 字段改 `*int`；新增 `tokensFrom(prompt, completion *int)` 作三协议**唯一**折算点（任一 nil → false）；`usageFrom` 本身未改；半报口径定为「任一缺失即未上报」

**Bug 2（更严重）｜DDL `prompt_tokens NOT NULL` 与「未上报写 NULL」冲突 → 统计记录静默写入失败 → 软限流完全失效**
- 现象：`recordCall` 失败只 `log.Printf`、业务照常成功；凡上游不返 usage 的调用统计全丢；`CountInWindow` 恒为 0 → `reject` 永不触发
- 根因：DDL `NOT NULL DEFAULT 0` vs 仓储注释「nil 落 NULL」vs 统计 SQL 只依赖 `tokens_reported` 标记，三处口径矛盾
- 修复（方案 A）：去掉 `NOT NULL` + **幂等** `ALTER TABLE ... ALTER COLUMN ... DROP NOT NULL`（关键：`CREATE TABLE IF NOT EXISTS` 不改已存在的列，存量环境必须靠 ALTER 才能真正修好）
