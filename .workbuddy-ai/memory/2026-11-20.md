### 关键架构决策（后续 3 菜单照此扩展）
- **team-only 表不进 FOREACH 循环**：`rdc_requirements` / `rdc_req_key_sequences` 只建在 `team` schema，仓储固定绑定 `PartitionTeam`、不用 `Partitioned[T]`。理由：RequireTeamMode 是硬边界，不为用不到的 solo 造空表（先例：project_members）。
- **需求编号**：`REQ-YYYYMMDD-NNN`（3 位，宽度常量 `contract.ReqSeqWidth`）。repository 同事务 `INSERT ... ON CONFLICT(day) DO UPDATE SET next_seq=s.next_seq+1 RETURNING s.next_seq` 原子分配；严禁 count(*)+1。**PG16 坑**：UPSERT 里裸 `next_seq` 会报 42702 ambiguity，必须用表别名 `AS s` 限定。
- **公司隔离**：`creator_user_id` 裸 TEXT 不建 FK（沿现有惯例），创建人姓名 JOIN users→people；所有查询先 `repository.ScopeFilter(0,'r',scope)`，越界 404 不泄漏存在性。
- **内置角色菜单自动授权陷阱（重要）**：`ReconcileBuiltinMenus` / `CreateBuiltinIfMissing` 原都用 `AllMenuKeys()` 全量塞给内置角色。给 `contract.Menu` 加 `AutoGrantBuiltin bool json:"-"`（现有 10 项 true、4 个 RDC 菜单零值 false），新增 `DefaultMenuKeys()` 供这两处使用；`AllMenuKeys()` 语义不变（超管全量/新建角色默认全量仍用它）。**两处播种路径都要改**，只改 Reconcile 会留"新建公司要到下次启动才清掉"的窗口。
- **solo 超管**：`allPermissions()` 不区分模式，前端 PermissionGate 会放行 solo 超管，新增 `TeamModeGate`（体验层，包在 PermissionGate 外）挡非 team；真边界是后端 `RequireTeamMode`。Sidebar 不改（solo 白名单天然不含 /rdc/*）。
- 写点独立：勾菜单自动得读点，写点须作为 Action 显式勾（D1，QA 补测试 `TestDerivePermissionsRDCWriteIsIndependent` 钉住）。
