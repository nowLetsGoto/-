## 2. 第一版最终范围（更新后的 P0）

### 2.1 P0 全量清单（原 7 条 + 新增 3 条，逐条可验证）

| 编号 | 需求 | 可验证的验收标准 | 来源 |
| --- | --- | --- | --- |
| P0-1 | 上传页 | 可选 / 拖入 `.apk`、`.ipa`；环境与平台必填；提交后可见该包下载页地址 | 原 P0 |
| P0-2 | 上传接口 | 包文件与元数据持久保存，服务重启后仍可查询与下载；返回可访问的下载页地址 | 原 P0 |
| P0-3 | 按环境 / 平台查询列表接口 | 环境必选、平台可选；结果只含该环境包、按上传时间倒序；每条含平台、应用名、版本、大小、时间、更新说明、下载页地址 | 原 P0 |
| P0-4 | 包列表页 | 四环境一级切换 + 平台筛选生效；空环境有空状态；点击进入独立下载页 | 原 P0 |
| P0-5 | 独立下载页 | 每包独立地址、可复制转发、手机浏览器可打开；展示应用名、环境、平台、版本、大小、时间、更新说明 | 原 P0 |
| P0-6 | 下载接口 | 点击按钮取到与上传内容一致的原始 `.apk` / `.ipa` 文件 | 原 P0 |
| P0-7 | 基础校验与反馈 | 类型 / 大小 / 必填 / 失败 / 空态均有可读文案，不出现空白页 | 原 P0 |
| **P0-8** | **下载二维码** | 每个包的下载页展示一枚**可扫码**二维码；扫码打开的确为该包下载页，且页面信息与列表一致；内容为完整绝对地址（见 §2.2） | 本次新增（C1） |
| **P0-9** | **自动解析包名 / 版本号** | 上传 `.apk` 后表单自动带出应用名、包名、`versionName`、`versionCode`；上传 `.ipa` 后自动带出应用名、`CFBundleIdentifier`、`CFBundleShortVersionString`、`CFBundleVersion`；字段可人工改；解析失败仍上传成功（见 §2.2） | 本次新增（C2） |
| **P0-10** | **下载次数** | 列表页每行与下载页均展示同一口径的次数；新包为 0；成功下载一次后两处均为 1（允许短暂更新延迟）；仅浏览 / 扫码不增加（见 §2.2） | 本次新增（C3） |

### 2.2 新增三项的产品定义

**① 二维码（P0-8）**

| 项 | 产品定义 |
| --- | --- |
| 展示位置 | **下载页必显**，与「下载 / 安装 App」按钮并列或紧邻；手机浏览器下可读可扫（尺寸 / 容错由架构师定，产品要求手机默认相机可识别） |
| 二维码内容 | 该包下载页的**完整绝对地址**（含协议 + 域名 + 包定位信息），可复制、可在任意设备打开；**禁止相对路径，禁止仅本机可达地址**（如 localhost / 127.0.0.1）；同一包生命周期内内容稳定，不含鉴权、有效期、安装控制信息 |
| 列表页建议 | **建议第一版不增加列表页二维码入口**。理由：① 列表页主任务是「按环境 + 平台定位包」，一行已承载平台 / 应用名 / 版本 / 大小 / 时间 / 下载次数 / 操作，再放入二维码会挤占信息密度；② 扫码发生在「拿到链接给手机」的环节，用户路径是先进入下载页再扫或转发，列表页放码使用率低；③ 不增加列表接口出参与渲染逻辑，符合「简单不冗余」；④ 后续若需打印物料或群内分发，可在 P1 于行操作列加「二维码」弹层，复用同一地址生成逻辑，成本低 |
| 部署约束提示 | 「绝对地址且手机可访问」是本次新增的产品硬约束，**其域名与网络可达性由架构师在 Q2 中一并回答** |

**② 自动解析（P0-9）**

| 项 | 产品定义 |
| --- | --- |
| 必解析字段 | Android：应用名（app label）、包名 `applicationId`、`versionName`、`versionCode`；iOS：应用名（`CFBundleDisplayName` / `CFBundleName`）、`CFBundleIdentifier`、`CFBundleShortVersionString`、`CFBundleVersion` |
| 顺带记录 | 文件大小、平台（由文件类型判定）、上传时间、更新说明（来自表单）。**应用图标不纳入第一版解析**（用户勾选范围为包名 / 版本号，图标属 P1，避免扩大范围） |
| 表单交互 | 选定文件后自动解析并**自动带出**到对应表单字段（解析中显示加载态）；所有字段**始终可编辑、不锁定**；用户已手动改动的字段不再被解析结果覆盖，以用户值为准；未改动的字段由解析值填充。最终解析值与用户修正值统一成为该包元数据，列表页、下载页与未来 push 引用同一份结果（对应 R2） |
| 失败降级 | 任一字段解析失败、包损坏、解析异常或超时 → **绝不阻塞上传**：该字段回退到上传者已填值；未填则用文件名 / 占位值兜底；上传照常成功，成功卡片提示「部分信息未自动识别，可手动修正」。第一版**不提供上传后编辑**，提示仅用于告知，不引入编辑页 |
| 与 Q4 冲突处置 | 01-PRD §8 Q4 默认值**作废**；新结论为「服务端自动解析为主 + 表单手填为兜底与修正」。Q4 由待确认改为已确认，仅余技术子项交架构师（见 §5） |

**③ 下载次数（P0-10）**

| 项 | 产品定义 |
| --- | --- |
| 一次下载的定义 | 用户在下载页点击「下载 / 安装 App」并**成功取得安装包文件**（服务端成功响应一次取包请求）计 **1 次** |
| 不计入 | 打开 / 刷新下载页、扫码、复制地址、列表页浏览、上传、查询、失败的取包请求 |
| 起点与方向 | 包上传成功时为 0，只增不减；第一版无删除包能力，不定义清零 / 回退 |
| 展示位置 | ① 列表页每行新增「下载次数」列；② 下载页信息区展示「已被下载 N 次」；两处同一口径，允许短暂更新延迟 |
| 去重 / 并发 / 失败重试 | **由架构师定稿**，产品不设硬性规则；仅给出期望：同一用户短时间重复点击不应使数值明显虚高，且统计不得影响下载主流程的成功率与速度 |
| 与 Q7 冲突处置 | 01-PRD §8 Q7 默认「不做」**作废**；Q7 改为已确认要做，仅余去重等技术子项交架构师（见 §5） |

## 3. Push 平台接入预留（产品视角，**非功能需求**）

### 3.1 未来场景（第一版均不实现）

| 场景 | 描述 |
| --- | --- |
| S1 新包推送到测试群 | 上传成功后，把「环境 / 应用名 / 版本 / 下载页地址 / 二维码」自动发到对应测试群，省去人工转发 |
| S2 按环境订阅发版通知 | 测试同学只订阅 `hotfix` / `pre`，`prd` 发版通知给更大范围；不同环境对应不同接收方 |
| S3 CI 打包后自动发布并回推 | 流水线调用上传接口发布到指定环境，发布完成后把成功 / 失败结果回推给流水线或群 |

### 3.2 第一版必须稳定下来的东西（结构性约束，不是功能需求）

| 编号 | 需稳定对象 | 产品要求 | 为何将来不必改主流程 |
| --- | --- | --- | --- |
| R1 | 包的稳定唯一标识 | 上传成功即为每个包生成全局唯一、生命周期内不变的标识；下载页地址、二维码内容、查询与下载都以它定位 | 推送只需引用该标识，不必改动上传 / 查询 |
| R2 | 完整元数据 | 上传完成那一刻，环境、平台、应用名、包名、版本号、构建号、大小、上传时间、更新说明、下载页绝对地址、下载次数全部可读可用 | 推送消息可直接引用，无需「通知时再解析包」 |
| R3 | 机器友好的接口行为 | 上传 / 查询 / 下载三者行为与返回信息稳定、自描述、可预测，机器调用不依赖页面交互或人工步骤（契约由架构师定） | 未来 CI / push 平台可直接复用现成接口 |
| R4 | 唯一的「上传完成」时点 | 主流程中明确唯一节点：包文件与元数据均已保存、下载页地址已生成且可访问；未来所有通知只挂在这一节点 | 不出现「通知已发出、下载页却打不开」 |
| R5 | 订阅维度占位概念 | 未来订阅大概率按「环境 × 平台 × 应用」+「接收方 / 渠道」组织；第一版只需保证前三者是包数据中独立、明确、可区分的字段，**不建立任何订阅关系、不存接收方、不引入账号** | 未来加订阅规则不动包结构 |

### 3.3 明确边界（负面清单）

- **第一版不实现**：任何推送、通知、消息、Webhook、订阅、回调、CI 集成、开放 API Key、事件监听，以及任何为 push 新增的表单字段 / 页面 / 配置项；§6 中 E5（通知）、G5（CI 集成）、G6（检查更新）状态不变，仍为「否 / P2」。
- R1–R5 属「信息结构与边界清晰度」的非功能期望（并入 01-PRD §7 N3），**不进入 P0/P1/P2 需求池、不作为功能验收项**。

## 6. 一句话范围声明

**第一版做**：Android / iOS 包在 test / hotfix / pre / prd 四环境的上传、按环境 + 平台查询列表、独立下载页与下载、下载页二维码、包名与版本号等元数据自动解析（失败降级手填、绝不阻塞上传）、下载次数展示；**明确不做**：iOS 浏览器直接安装、任何推送 / 通知 / Webhook / 订阅 / CI 集成 / 开放 API Key、登录鉴权与成员体系、密码或回答问题安装、有效期与定时发布、渠道与统计报表、鸿蒙 / CDN / 多语言 / 大包分发、包删除与编辑、列表页二维码入口，以及任何为 push 预留而新增的表单字段或页面。
