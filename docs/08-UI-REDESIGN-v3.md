# 08 · 平台化 UI 重构 v3（结构 / 布局 / 主题 / 功能）

> 日期：2026-11-16 ｜ 状态：**P0 已实施（2026-11-16）**，P1 / P2 待排期
> 配套原型：`docs/design/v3-prototype.html`（单文件，浏览器直接打开，可切页）
> 效力：本文描述目标形态与落地顺序；与 `05-MODULE-ROADMAP` 的「不建占位菜单」冲突处，以本文 §7 的裁决为准。

## 1. 现状问题（为什么"没有分类和设计"）

| # | 现象 | 根因 |
| --- | --- | --- |
| P1 | 登录后直接落到「应用包」列表，空环境时整页只有两块大白板 | 平台没有「首页」，列表页被迫承担落地页职责 |
| P2 | 顶部导航只有一项「应用包」，其余板块无处安放 | 导航是**单板块**结构，pushy 热更新只能另开一套 |
| P3 | 包是一行行孤立记录，无法按应用聚合 | 缺少「应用 App」这个平台级主实体 |
| P4 | 筛选卡片 + 空态卡片各占一整块，信息密度低 | 容器化过度：该用工具栏的地方用了卡片 |
| P5 | 登录页青蓝、主站绿色 | 两套主题，没有统一 token |

## 2. 设计目标

1. **平台化**：一个侧边栏容纳多个板块，加板块 = 加一项 + 加路由，不改骨架。
2. **先看全局，再做单点**：登录后落到「概览」，用一屏回答"各环境现在是什么状态"。
3. **应用优先**：包与热更新都挂在「应用」下，共享 环境 / 平台 / 版本 三个维度。
4. **空状态有出路**：没有数据时给解释与下一步，而不是一句"暂无"。
5. **一套 token**：主站与登录页同色系，浅色 + 青蓝。

## 3. 信息架构

```
Dandelion 研发交付平台
├─ 概览            Overview      登录落地页：本周发布 / 应用×环境矩阵 / 最近发布 / 包分布
├─ 分发
│   ├─ 应用包      Packages      .apk/.ipa 上传、列表、下载页（现有能力）
│   └─ 热更新      Hotfix        pushy 类：按「应用 × 基线原生版本」发布 bundle、灰度、回滚
└─ 管理
    ├─ 应用        Apps          平台级主实体：名称 / 包名 / 平台 / 环境覆盖 / 热更新接入状态
    └─ 成员与权限  Members       多账号与角色（P3，当前仍是单管理员）
```

**「应用」是一级实体**，这是把 pushy 装进来的前提：热更新的发布对象不是"一个包"，而是"某个应用的某个基线原生版本"。

## 4. 布局

| 区域 | 规格 | 说明 |
| --- | --- | --- |
| 侧边栏 | 248px，浅青底 + 右侧 1px 分割线，sticky 满高 | 品牌区 / 分组导航 / 底部「显示规划板块」开关 + 账号 |
| 顶栏 | 58px，白底 + 下边框，sticky | 面包屑（板块 / 环境）、**全局环境切换**、搜索、主行动按钮 |
| 内容区 | 最大 1240px，padding 22/26 | 页面标题 + 副标题 → 主体 |
| 响应式 | ≤1080 双列降单列；≤900 侧栏变顶部横向滚动条 | 表格横向滚动，不压缩列宽 |

**关键变更：环境从"页面筛选"提升为"全局维度"**。理由：环境对所有板块都成立，写进 URL（`?env=prd`）后可跨板块保持；页面内只保留平台、排序等局部筛选。

## 5. 设计 token

```css
--ink: #0f2c36;          /* 正文 */
--ink-2: #33525f;        /* 次级正文 */
--muted: #5b7884;        /* 说明文字 */
--faint: #7d97a2;        /* 弱化标注（仅限 ≥14px 非关键文字） */
--line: #e3eef2;         /* 分割线 */
--bg: #f6fafb;           /* 页面底 */
--surface: #ffffff;      /* 卡片 */
--primary: #0369a1;      /* 主色：饱和天蓝，白底对比度 5.93:1（与登录页一致） */
--primary-strong: #0b5c73;
--primary-soft: #e4f3f8; /* 激活底 */
--ok: #127a5c;  --warn: #a45a0b;  --danger: #b42318;
```

- 字号：12 / 12.5 / 13 / 13.5 / 15 / 22（标题）。数字一律 `font-variant-numeric: tabular-nums`。
- 间距：4 的倍数，卡片内 14/16，卡片间 16，区块间 22。
- 圆角：卡片 12、控件 8、徽标 999。
- 阴影：只用于 hover 抬升与浮层，列表与卡片默认不投影（避免"处处浮起"）。

## 6. 组件与状态规范

| 组件 | 规范 |
| --- | --- |
| 统计条 | 一条通栏 + 内部竖分隔线，**不做四张独立卡片**；数值 26px/600，趋势小字用语义色 |
| 表格 | 表头 11.5px/弱色/浅底，行高 44，末行无边框；hover 用 `--surface-2` |
| 工具栏 | 与表格同一张卡内，用下边框分隔；平台用分段控件，其余用轻量按钮 |
| 空状态 | 插画（蒲公英线稿）+ 标题 + **解释性文案** + 主/次行动；**结果为空且无筛选时隐藏工具栏** |
| 徽标 | 环境/平台/状态三类，语义色只用于状态，不用于装饰 |
| 进度（灰度） | 8px 轨道 + 渐变填充，右侧固定比例标签，下方一行说明当前档位与下一步 |
| 动效 | 仅切页淡入 200ms（`cubic-bezier(.22,1,.36,1)`）与 hover；尊重 `prefers-reduced-motion` |

## 7. 与现有约定的冲突与裁决

| 冲突点 | 现状约定 | 本次裁决 |
| --- | --- | --- |
| 「不建占位菜单 / 空页面」（05-MODULE-ROADMAP） | 第一版绝不出现"敬请期待" | **生产环境仍然遵守**：只上「概览 / 应用包 / 应用」三个有后端的板块。原型里的「热更新 / 成员」标 `规划中`，仅用于评审；侧栏保留「显示规划中的板块」开关证明取舍 |
| `styles.css` 是唯一样式来源（06-FOLDER-LAYOUT） | 不允许拆分样式 | **允许页面级样式**：登录页已用 `login.css`（`login-` 前缀），本次同样按 `layouts/`、`pages/` 就近放，全部加前缀，不改全局变量 |
| 顶栏三段式 Layout | `Layout` 只有品牌 + 导航 + 上传 | 改为「侧边栏 + 顶栏」两段式；`Layout` 拆出 `Sidebar`，导航仍是**配置数组**，与 05 的"加板块=加一项"保持一致 |

## 8. 分阶段落地

### P0 · 骨架 + 概览 + 主题统一（✅ 已实施，未动数据库）

实际落地与计划的差异（均为缩小范围，不影响结构）：

- **应用页已上线**，但实现方式是「从四环境包列表派生」的只读视图（`pages/AppsPage.tsx`），P1 建 `apps` 表后换成真查询，页面结构不变。
- **顶栏搜索未做**：它需要跨应用/包名的后端搜索接口，属 P1；按「不放占位控件」的规矩没有放出输入框。
- **概览的「待处理」改为「解析降级」**：原型的待办数没有数据源，换成 `metaSource=fallback` 的真实计数。
- **公开下载页不再套骨架**：`/d/:id` 独立居中渲染，扫码的人看不到内部导航。

| 项 | 改动 |
| --- | --- |
| Layout | 抽出 `components/Sidebar.tsx`，`Layout` 改为侧栏 + 顶栏 + 内容 |
| 概览页 | 新增 `pages/overview/OverviewPage.tsx`；数据先用现有 `listBuilds` 对四环境各查一次聚合（**不新增后端接口**） |
| 环境全局化 | 环境写入 URL `?env=`，顶栏切换；`ListPage` 改为读全局环境，删掉页面内环境筛选 |
| 应用包页 | 筛选卡 + 空态卡合并为「工具栏 + 表格」一张卡；空态换成引导式 |
| 主题 | 全站 `--color-primary` 系列切到青蓝，与登录页统一 |
| 路由 | `/` → 概览，`/packages` → 应用包，`/upload`、`/d/:id` 不变；旧 `/?environment=` 链接重定向到 `/packages?env=` |

### P1 · 应用实体（需要建表）

- `apps` 表：`id, name, package_id, platforms, icon_text, created_at`
- `builds` 增加 `app_id`（FK），保留 `app_name/package_id` 作为快照，避免历史数据迁移阻塞
- 新增 `GET /api/v1/apps`、`GET /api/v1/apps/{id}`；概览的「应用×环境」矩阵改为真数据
- 前端新增 `pages/apps/AppsPage.tsx`；上传表单的「应用名」改为**选择或新建应用**

### P2 · 热更新板块（pushy 类）

数据模型（最小集）：

```
update_bundles
  id, app_id, environment, platform,
  baseline_version,          -- 基线原生版本，如 1.4.2
  bundle_version,            -- bundle 序号（v12）
  compat_range,              -- 如 ">=1.4.0 <1.5.0"
  file_path, file_size,
  rollout_percent,           -- 0-100
  status,                    -- draft | graying | live | paused | rolled_back
  created_at, created_by
```

接口：

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/v1/updates` | 需登录 | 发布 bundle（multipart） |
| GET | `/api/v1/updates?environment=&appId=` | 需登录 | 版本线列表 |
| PATCH | `/api/v1/updates/{id}/rollout` | 需登录 | 调整灰度比例 / 暂停 / 恢复 |
| POST | `/api/v1/updates/{id}/rollback` | 需登录 | 回滚（**新增一条记录指回上一版，不删历史**） |
| GET | `/api/v1/updates/check` | **公开** | 客户端拉取：`appId + platform + nativeVersion` → 命中的 bundle 与灰度判定 |

要点：灰度判定按 `设备标识 hash % 100 < rollout_percent`，同一设备结果稳定；`check` 与下载页一样必须公开（客户端没有账号）。崩溃率自动暂停依赖客户端上报，属 P3，不要在第一版承诺。

### P3 · 成员与权限 / 通知

多账号、角色（上传 / 发布 / 灰度 / 只读）、发布通知。当前登录是单管理员，P3 需要把令牌载荷从"到期时间"扩展为"用户 id + 到期时间"。

## 10. 验收标准（设计层）

- [ ] 登录后 3 秒内能回答"四个环境各自最新版本是什么"
- [ ] 任一板块在无数据时都有解释 + 下一步，不出现"整页大白板"
- [ ] 侧边栏新增一个板块只需改导航数组 + 加一条路由，`Layout` 不动
- [ ] 全站主色与登录页一致，无第二套绿/蓝混用
- [ ] ≤900px 宽度下：导航单行可滚动、表格横向滚动、无文字竖排
