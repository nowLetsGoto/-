# 平台集成 · R2 与隧道配置方案

> 2026-11-27 · 起因：换机器部署时 R2 与隧道都要手工改环境变量、手工跑 cloudflared 命令
> 目标：把「能进页面的配置」搬进页面，把「不能进页面的部分」讲清楚为什么不能
> 状态：方案已定，待实施

## 1. 先分清两件常被混为一谈的事

R2 与隧道**没有直接关系**，它们是两条独立的路径。混着讲会导致设计错位——
比如以为「隧道配好了下载就快了」，或者「R2 配好了公网就能访问了」，都不成立。

| | 隧道（cloudflared） | R2（对象存储） |
| --- | --- | --- |
| 作用 | 让外网能访问这台电脑 | 让文件存到云端 |
| 传输什么 | 网页 HTML/JS/CSS、API 的 JSON | 安装包文件本体 |
| 单次数据量 | 几百 KB 级 | 单个 100 MB 级 |
| 挂了会怎样 | 网站打不开，但文件没丢 | 下载降级走本机，慢但不失败 |
| 配置形态 | 本机授权文件 + 浏览器 OAuth | 纯参数（id / key / secret / bucket） |

### 实际的数据流

```
用户扫码
   ↓
dandelion.dreamgarden.world         ← 隧道，转发到本机 :10088
   ↓  页面加载完成，点「下载」
download.dreamgarden.world/xxx.apk  ← R2 自定义域名，直连 Cloudflare 边缘
```

两个域名是两套东西：前者指向**你的电脑**，后者指向**Cloudflare 的存储**。

代码可验证这一点——`storage/r2.go` 的 `DownloadURL` 只要配了自定义域名就直接返回 CDN 地址：

```go
func (r *R2) DownloadURL(ctx context.Context, key string, ttl time.Duration) (string, error) {
	if r.cfg.PublicBaseURL != "" {
		return r.PublicURL(key)   // → download.dreamgarden.world，不经过本机
	}
	// 没配自定义域名才走 R2 签名直链
	return out.URL, nil
}
```

**结论：下载安装包时，文件流量不经过隧道。**

### 一个必须知道的例外

R2 未配置或不可用时，下载会降级走本机磁盘（`localPull` / 本地流式）。
这时 119 MB 的包**会真的从本机经隧道传出去**，家宽上传带宽通常只有几十兆，
体验会非常差。

这正是 R2 的第一个价值：**把大文件流量从家宽移走**。

上传也同理分两条路，都不靠隧道传文件：

- 小包：浏览器 →（经隧道）本机服务端 → 服务端推 R2
- 大包：浏览器 → R2 直传（预签名 URL，绕过本机，`build_direct_upload.go`）

## 2. 为什么要做成页面配置

| 现状痛点 | 具体表现 |
| --- | --- |
| 换机器全手工 | R2 五个参数写在 `.env`，隧道要跑 `tunnel login` + `create` + 手写 `config.yml` |
| 改一次要重启 | 环境变量在启动时读入，改完必须重启进程 |
| 无处查看状态 | 隧道连没连上、R2 通不通，只能靠命令行 |
| 凭据分散 | `.env` 明文、plist 明文、`~/.cloudflared/` 文件，三处各管一部分 |

## 4. R2 配置页（可写）

### 4.1 字段与回显策略

| 字段 | 页面行为 | 说明 |
| --- | --- | --- |
| Account ID | 明文回显 | 非敏感，泄露不足以造成损失 |
| Access Key ID | 明文回显 | 非敏感，单独泄露无法签名 |
| Secret Access Key | `••••••••` + 「替换」按钮 | **永不回显明文** |
| Bucket | 明文回显 | 非敏感 |
| 自定义域名 | 明文回显 | 非敏感，但影响下载是否可用 |
| 启用开关 | 开关 | 关掉等同纯本地下载 |

Secret 只在「用户主动替换」时提交一次，之后接口只返回 `secretConfigured: true`。
这与 `system_settings.api_key` 存摘要的思路一致——**能不给就不给**。

### 4.2 连接测试必须测两件事

不能只测「能不能连上 R2 API」，还要测「自定义域名能不能取到对象」。
两者是不同的事，**第二件才是用户真正会遇到的故障**：

| 测试项 | 方法 | 失败意味着 |
| --- | --- | --- |
| 凭据与桶 | `PUT` 探针对象 → `StatObject` → `DELETE` | key/secret 错、桶名错、桶无权限 |
| 自定义域名 | `GET <PublicBaseURL>/<探针 key>` | DNS 没解析、R2 未开公共访问、域名拼错 |

只测第一项会出现最坏情况：页面显示「连接正常」，用户扫码下载却 404。

失败原因必须区分开（凭据 / 桶 / 域名 / 网络），笼统的「连接失败」无法排查。

### 4.3 热生效

配置保存后立即生效，不重启进程。实现见第 6 节。

响应带 `appliedAt`，页面显示「已生效」，与「需重启」明确区分。

## 5. 隧道页（只读 + 重连）

### 5.1 为什么不能做成可编辑表单

这是本方案最需要讲清的一点。**把隧道配置做成页面输入框，技术上做得到，但一定会出问题。**

三个硬约束，每一个都不是「努力一下就能绕过」：

**① 登录必须人工点浏览器**

`cloudflared tunnel login` 会打开浏览器让你选账号、点「授权」。这是 OAuth 流程，
本质是把账号权限授予这台机器。任何声称「页面一键登录 Cloudflare」的实现，
只能是让用户手工复制 `cert.pem` 粘到一个输入框里——那不是自动化，是把文件搬运
伪装成登录，还多存了一份凭据在数据库。

**② 凭据文件必须在本机**

```
~/.cloudflared/cert.pem                     账号级凭据
~/.cloudflared/<tunnel-id>.json             隧道级凭据（含 secret）
~/.cloudflared/config.yml                   隧道 ID 与本地端口映射
```

cloudflared 进程启动时读这些文件。若把它们存进数据库，新机器还得再写回磁盘——
**绕一圈等于多一份泄露面，一点没省事**。

**③ DNS 记录在 Cloudflare 控制台**

`dandelion.dreamgarden.world` 的 CNAME 指向 `<tunnel-id>.cfargotunnel.com`，
这条记录只能去控制台改。页面改了本地配置也不会让域名生效。

### 5.2 所以页面该做什么

只做「查看 + 重连」：

```
状态      ● 已连接（4 条边缘连接）
隧道 ID   b23fb73f-0a1a-4625-809c-04cdd7eb62e0
公网域名  dandelion.dreamgarden.world
本地上游  127.0.0.1:10088
[重新连接]  → launchctl kickstart com.dandelion.tunnel
```

**能看、能重启、不能改。** 改配置走脚本（第 7 节）。

这样划分不是限制功能，而是承认边界：**页面的价值是「看得见状态、按得动重启」，
不是「当文件编辑器的遥控器」**。硬要做成编辑器，会引入
「页面改了但文件没改」或「文件改了但页面不知道」的不一致，比不做更糟。

### 5.3 状态数据从哪来

两种来源各有取舍，页面按「快慢分离」使用：

| 时机 | 来源 | 耗时 |
| --- | --- | --- |
| 页面加载 | 读 `config.yml` + 探活 `PUBLIC_BASE_URL` | 毫秒级 |
| 点「检查」 | `cloudflared tunnel info <name>` | 1–2 秒 |

只探活 URL 无法区分「隧道断了」与「后端挂了」；只跑 `tunnel info` 又太慢，
不适合每次进页面都跑。两者结合才既快又准。

## 6. 热生效的实现

### 6.1 为什么不能只换指针

`BuildService.r2` 目前是构造函数注入的指针，进程内复用。改造面：

| 项目 | 数量 |
| --- | --- |
| `s.r2.<method>` 直接调用 | 17 处 |
| `s.r2 == nil` 判空 | 15 处 |
| 涉及文件 | 9 个 |
| `s.sessions == nil` 判空 | 4 处 |

如果只在保存时替换指针，会出现这个问题：

```
下载进行到 60%  →  用户保存新凭据  →  指针变了
                →  同一个下载的后续读取走新凭据  →  失败
```

### 6.2 正确结构：一次操作取一次快照

```go
type R2Registry struct {
	cur atomic.Pointer[storage.R2]
}
func (r *R2Registry) Get() *storage.R2      { return r.cur.Load() }
func (r *R2Registry) Swap(next *storage.R2) { r.cur.Store(next) }
```

调用点改造模式——**在函数入口取一次，全程用同一个局部变量**：

```go
// 改造前
if s.r2 == nil { return }
err := s.r2.Put(...)

// 改造后
r2 := s.r2.Get()
if r2 == nil { return }
err := r2.Put(...)      // 不重复 Get()
```

重复 `Get()` 会让一次操作中途换凭据，这正是要避免的。

### 6.3 必须一起换的东西

`sessions`（浏览器直传会话仓储）与 `r2` 生命周期绑定，
`build_direct_upload.go` 里有 4 处 `s.sessions == nil` 判断。
切换 R2 时两者必须同时替换，否则会空指针。

### 6.4 密钥加密

R2 Secret 必须**还原明文**才能签名请求，因此不能用摘要，只能加密：

```
key        = HKDF(AUTH_SECRET, salt="r2-secret", len=32)
ciphertext = "v1:" + AESGCM.Seal(nonce, plaintext)
```

与 `system_settings.api_key` 的差别要说清：

| | api_key | R2 Secret |
| --- | --- | --- |
| 用途 | 只做比对 | 需还原后签名 |
| 存法 | SHA-256 摘要 | AES-GCM 密文 |
| 原因 | 验证不需要原文 | 签名必须有原文 |

**版本前缀 `v1:` 不是装饰**：将来换算法时靠它识别旧数据，否则无法平滑迁移。

**边界**：`AUTH_SECRET` 变更会导致所有密文解不开。启动时检测解密失败并提示
「R2 凭据无法解密，请在平台集成重新填写」，而不是让服务崩掉。

## 7. 新机器引导（脚本，不进页面）

```
scripts/setup-cloudflare.sh
├── 检查 cert.pem       → 缺失则提示 cloudflared tunnel login
├── 检查隧道是否存在     → 缺失则提示 tunnel create dandelion
├── 生成 config.yml     → 写入隧道 ID 与本地端口
└── 打印 DNS 配置指引    → 明确说明必须去控制台改 CNAME
```

**必须诚实告知用户的三件事**（页面无法替代）：

1. `tunnel login` 必须浏览器授权
2. 隧道凭据文件必须留在本机
3. DNS 记录必须去 Cloudflare 控制台配

## 8. 实施顺序与验收

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| P1 | 加密工具 + 表字段 + R2 配置读写接口 | 存进去能读出来，密文可解密，错密钥能识别 |
| P2 | R2Registry + 32 处调用点改造 | 全量测试通过；切换过程中在途任务不失败 |
| P3 | 前端 R2 页 + 连接测试 | 凭据错/桶错/域名错能给出不同提示 |
| P4 | 隧道只读页 | 状态准确；重连有效；无编辑入口 |
| P5 | `setup-cloudflare.sh` | 新机器从零跑通，含缺凭据时的清晰指引 |

**P2 是风险点。** 32 处改造一次性做完，出问题难以定位。
分两步提交：

1. 先引入 Registry 但保持单例语义（只在启动注入一次），跑全量测试确认零回归
2. 再开放 `Swap`，并补「切换时在途下载不受影响」的测试

## 9. 明确不做的事

| 不做 | 理由 |
| --- | --- |
| 页面配置 `AUTH_SECRET` / `DATABASE_URL` | 循环依赖：读配置需要数据库，改数据库需要配置 |
| 页面触发 `cloudflared tunnel login` | OAuth 必须浏览器人工授权，无自动化路径 |
| 页面改 DNS 记录 | 需 Cloudflare API Token，属于账号级操作，超出本系统边界 |
| 把 `cert.pem` 存数据库 | 本机凭据进库等于多一份泄露面，且新机器仍需写回磁盘 |
| 隧道配置做成可编辑表单 | 会出现「页面改了但文件没改」的不一致，见 5.1 |
