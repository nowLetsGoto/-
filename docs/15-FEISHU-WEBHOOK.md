# 飞书发布通知接入

<!-- 职责：说明 CI/后台发布到飞书下载卡片的配置与验收；输入：公司账号、机器人配置、CI 密钥；输出：接入步骤；边界：不包含真实密钥，不承诺消息持久化或自动补发。 -->

发布成功后，Dandelion 异步发送飞书卡片。“打开下载页”按钮直接使用服务端生成的 `downloadPageUrl`，完整保留单版本 `shareToken`。CI 和后台手工上传复用同一条通知链路。

## 1. 配置机器人和平台

1. 在飞书目标群中进入“设置 → 群机器人 → 添加机器人 → 自定义机器人”。
2. 保存机器人 Webhook 地址，格式为 `https://open.feishu.cn/open-apis/bot/v2/hook/<机器人凭证>`。
3. 如启用“签名校验”，复制飞书提供的密钥。如配置关键词，可使用 `应用更新提醒`，正式及测试卡片标题均包含此词。
4. 用目标公司的管理员账号登录 Dandelion 团队模式，进入“平台集成 → Webhook”。页头显示当前配置归属。
5. 选择“飞书机器人”，填写地址与对应签名密钥，启用 Webhook，勾选要显示的信息。“下载页地址”为必选项。应用更新提醒建议勾选应用名称、平台、版本号、构建号、文件大小、发布时间及更新说明。
6. 点击“保存”，再点击“发送测试消息”。只有 HTTP 成功且飞书响应 `code=0` 时才显示投递成功。测试卡片不提供下载按钮；真实包发布后才会出现有效的分享入口。

“飞书签名密钥”与 CI 上传的“API Key”用途不同。前者用于飞书验证消息来源，后者用于 CI 上传，均不会作为下载权限发送给群成员。

官方参考：[自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。

## 2. 接入 CI

“平台集成 → 外部 API”中的 Key 在生成时自动归属于当前账号所在公司。已有明文直接写入 CI 密钥变量即可；遗失明文才需要轮换。超级管理员的平台兜底 Key 不允许用于 CI 上传。

配置 CI 密钥变量 `DANDELION_API_KEY`、分发服务地址 `DANDELION_URL` 和项目标识 `DANDELION_PROJECT`：

```bash
curl --fail-with-body -sS -X POST "${DANDELION_URL}/api/v1/open/builds" \
  -H "X-API-Key: ${DANDELION_API_KEY}" \
  -F "project=${DANDELION_PROJECT}" \
  -F "file=@./app-release.apk" \
  -F "environment=test" \
  -F "platform=android" \
  -F "changelog=本次构建更新说明"
```

成功为 HTTP 201，下载页地址位于 `data.downloadPageUrl`。服务端会自动触发通知，CI 无需再次调用飞书。通知失败不会把上传成功改为失败。

## 3. 网络与真实包验收

`PUBLIC_BASE_URL` 是下载地址唯一基址；修改后重启 Go 后端。它必须指向测试人员可以访问的分发页面，开发时端口要与 Vite 实际监听端口一致。

- CI 能访问上传接口。
- Dandelion 后端能访问飞书 Webhook。
- 手机或电脑能访问分发地址。内网地址适用于同网段或 VPN；跨网络使用应配置可达的固定 HTTPS 地址。

上传一个真实包，确认群中出现“应用更新提醒”。卡片将平台显示为 Android/iOS/鸿蒙，版本号与构建号合并为 `26.11.103(Build 2076)`，文件大小使用 MB 等单位，更新时间统一为北京时间（含秒），更新内容读取发布时的 `changelog`。CI 的环境、真机/模拟器、模块和构建人等描述可统一写入 changelog；未填写时显示“发布方暂未填写更新说明”。

用未登录 Dandelion 的浏览器点击“打开下载页”，核对应用、版本和环境，并下载文件。同一下载页可切换该应用其它已授权环境、平台和历史版本，二维码和下载入口跟随所选包。分享无效时页面显示失效，不会跳过授权校验。

## 4. 排错与投递边界

| 现象 | 检查项 |
| --- | --- |
| `code=19021` | 签名密钥、机器人是否启用签名、服务器时间 |
| `code=19022` | 机器人 IP 白名单中的后端出口 IP |
| `code=19024` | 机器人关键词，可配置为 `应用更新提醒` |
| `code=11232` | 机器人限流，稍后重试测试消息 |
| 上传 401 | CI Key 是否缺失、错误或已被轮换 |
| 上传 403 | 是否使用了没有公司归属的平台兜底 Key |
| 消息成功但页面打不开 | 分发基址、端口、网络和代理配置 |

每家公司沿用一份通知配置。已有公司配置优先使用自己的配置；尚无配置行时保持原有平台兜底行为。需要专属群时，应在公司账号下保存通知配置。

正式通知异步发送，单次超时 10 秒，HTTP 与飞书业务失败均记录日志；机器人凭证地址、签名密钥和分享链接不写入投递日志。首版没有持久队列或自动重试，进程重启可能中断未完成通知。真实机器人配置完成后，需要按第 3 节完成端到端验收。
